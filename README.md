# Halpha Monitor

稳定的价值取向、独立边界、第三方复用顺序和个人项目复杂度约束见 [项目原则](docs/PROJECT-PRINCIPLES.md)；AI 开发入口见 [AGENTS.md](AGENTS.md)。

这是一个独立的本地公开市场监控服务，不属于 Halpha App/Executor 产品运行时，也不取得账户、凭据或交易能力。“只读”指不会改变交易所或产品事实；页面只会修改本服务自己的采集条件、启停状态和人工校正记录。

## 本地隐私门禁

首次克隆后启用仓库自带的提交与推送门禁，并可随时扫描全部受 Git 管理或可能进入 Git 的文件：

```powershell
git config --local core.hooksPath .githooks
python .githooks/check_local_privacy.py --self-test
python .githooks/check_local_privacy.py --all
```

门禁命中时只显示类别与位置，不回显内容；不得使用 `--no-verify` 绕过。服务只为公开市场采集访问已声明来源，不包含遥测、错误自动上报或本地数据上传。

当前显式注册六个监控：

- Binance C2C 核算：比较公开 C2C 广告和现货一档；
- BTC 专业情报：把 BTCUSDT 的月频 Faber 状态、日频 Donchian 20/30/60/90 状态、因果确认的 4 小时支撑/阻力与前向事件账本，和原有 30m/1h Smart Money 语境整合到一个只读决策页；
- 山寨币异动雷达：对 Binance USDⓈ-M USDT 永续合约做全市场初筛，以闭合 5m K 线、BTC 相对表现、资金费率和 OI 变化输出可解释的异动阶段与尾声风险，并用闭合 UTC 日线标记当前价格位置、快速涨跌、区间高低位和上一轮完整拉升峰值；
- BTC 市场关联与相对强弱：基于 Binance Spot 闭合 UTC 日线，记录固定资产范围相对 BTC 的相关性、Beta、波动倍数和 7/30/90 日相对强弱；
- A股与港股通回购情报：汇总通过质量门的 A 股官方回购披露、港交所实际回购日报以及沪深两条港股通资格，计算实际执行天数、累计股数/金额、回购均价、现价位置、市值占比和最新公开业绩输入，并形成覆盖度降权的“回购吸引力”；该指标用于安排研究顺序，不是上涨概率或交易指令。
- 市场关键事件日历：汇总美国宏观发布、美联储议息日期和最近官方通胀/就业结果，按距离发布时间和事件类型突出当前交易需要提前考虑的未来事件；准备优先级不是涨跌判断或交易指令。

## 运行

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m halpha_monitor
```

浏览器打开 `http://127.0.0.1:8790/`。服务只绑定本机回环地址。

页面会把当前选中的监控写入地址栏的 `monitor_id` 参数；刷新浏览器或复制该地址重新打开时，仍会进入同一监控。山寨币异动雷达还用 `view` 参数保留“异动候选 / 价格位置 / 异动强度历史 / 后续行情检验”子页。地址中的监控已不存在时，页面会移除失效参数并回到第一个已注册监控。

BTC 专业情报和山寨币异动雷达使用前后台双频采集。只有浏览器标签页可见且当前停留在对应监控时，页面才每 15 秒续约一次 45 秒的进程内观察租约；BTC 专业情报在观察模式下每 60 秒采集，山寨币异动雷达在观察模式下每 300 秒采集。页面隐藏、关闭或切换到其他监控后不再续约，租约到期即恢复后台周期：BTC 专业情报 600 秒，山寨币异动雷达 3600 秒。多个可见标签页只延长同一个监控租约，刷新请求复用调度器现有的合并事件，不建立队列、不写浏览器标识或租约到 SQLite；监控关闭、交易时段门禁或来源限流退避仍优先于观察模式。

每项监控都可以在页面中独立开启或关闭，选择持久化到同一个 SQLite。关闭不会删除历史，也不会把后续空档记成故障。C2C、BTC 专业情报和市场关键事件日历再次开启后会立即请求一轮采集；回购情报的“开启”只表示允许调度，自动采集仍受下述 A股/港股交易时段约束。C2C、BTC 专业情报和市场关键事件日历默认开启；山寨币异动雷达、BTC 关系监控和回购情报监控默认关闭。

回购情报按交易所日历和北京时间只在两地交易时段并集自动刷新：A股 `09:15–11:30、13:00–15:00`，港股全日市 `09:00–12:00、13:00–16:10`；节假日和港股半日市由 `exchange-calendars` 的 `XSHG` / `XHKG` 日历判定。闭市时即使监控保持开启，也不创建采集轮次、不发出公网请求，页面保留最近已提交的静态历史数据并把下一次页面读取延后到下个交易窗口。标题区的“手动刷新”可在任意时间显式请求一轮，重复待执行请求会合并；交易日历超出已知范围或无法解析时自动采集会失败关闭，页面明确提示并仍保留手动刷新。

顶部只汇总运行事实：监控是否运行、当前采集负载、近 60 秒实际发出的公开 HTTP 请求数、计划采集轮次和最近完成时间。负载占用按当前允许自动采集的监控最近或当前一轮耗时除以各自采集周期后求和，低于 25% 为低、25% 至 74% 为中、75% 及以上为高；闭市中的回购监控不计入计划轮次。它属于公开网络采集活动的运行指标，不是 CPU 使用率或交易所请求权重。桌面端左侧监控列表在长页面滚动时保持可用，并可折叠为显示短名称、状态底色与右侧色条的紧凑导航；绿色表示监控中，蓝色表示开启但当前处于闭市等静态待机状态，灰色表示已关闭，黄色左边线和底色只表示当前选中项。折叠状态仍可直接切换监控并记在当前浏览器中，窄屏继续显示完整名称。列表已逐项显示运行状态，不再保留重复的状态统计面板。近期采集问题通过每个监控标题区的“诊断日志”按钮在弹窗中按需查看，所有监控使用同一入口和样式。数据缺口不再汇总成笼统的“部分来源异常”；受影响的币种、范围或字段在对应表格内就地标记，未标记的展示值均为已通过校验的事实。

数据表保留局部横向滚动，全部列都可点击表头在正序和倒序之间切换，空值始终排在有值记录之后。回购情报清单、山寨币异动候选表和价格位置表纵向随整个页面滚动，不再嵌套第二条纵向滚动条；当清单继续延伸到当前视口下方时，页面底部显示与表格同步的横向滚动条，用户无需先到整页末尾即可查看右侧列。清单超过 50 条时先对全部筛选结果排序，再按每页 50 条展示，长页面滚动后可用右下角入口回到顶部。非直观列的表头带有信息标记，鼠标悬停可查看计算或分类规则。山寨币异动雷达把四个标签放在不会随标签变化的标题和运行控制下方，标签以下才是各视图内容；候选标签下面只保留本轮摘要与候选表，价格位置标签显示日线状态筛选与位置表，历史范围只在历史标签出现并支持 1/3/6/12 小时和 1/3/7/14/30 天。回购情报投影不显示无意义的价格历史控件。山寨币异动雷达两个清单中的整行均可在新标签页打开对应 Binance USDⓈ-M 永续合约行情；该跳转只是用户发起的公开页面导航，不会读取账户或发送订单。

页面中的“采集条件”可以修改核算金额和支付方式；配置写入同一个 SQLite，监控已开启时保存后立即请求一轮新采集。默认核算金额为 `2000 CNY`，默认启用银行卡、支付宝和微信。

重新启动终端或服务后生效。普通运行、样本、诊断和原始响应默认保留 90 天，可用 `--retention-days` 调整。BTC 4 小时结构事件 revision 默认保留 1825 天且最多保留 20000 个事件，分别用 `--btc-structure-retention-days` 和 `--btc-structure-max-events` 调整；只保留部署后实际冻结的前向事件，不把启用前的历史触碰倒灌为预测记录。BTC 月频研究账本最多保留最近 240 个完整月及其信号/执行 revision，不受普通样本保留期影响。回购实体 revision、人工校正和仍被引用的原始证据默认保留 1095 天，分别用 `--buyback-retention-days` 和 `--buyback-evidence-max-mib` 调整保留期与证据目录上限；默认上限为 2048 MiB。证据目录位于数据库同目录的 `evidence/buyback/`。市场事件从首次成功采集时点开始独立保存 revision，默认保留 1095 天，可用 `--market-event-retention-days` 调整；不会把启用前的旧事件倒灌为历史。

BTC 专业情报、山寨币异动雷达与 BTC 关系监控的规范化闭合 K 线缓存分别位于数据库同目录下的 `cache/btc-intelligence/`、`cache/altcoin-radar/` 和 `cache/btc-relationship/`。缓存只用于避免同一闭合周期重复下载，不是第二数据库或研究证据；来源落后于当前应有截止点时不会用于生成新状态、结构或事件。

服务未收到显式 `OPENBLAS_NUM_THREADS` 配置时默认使用 1 个 OpenBLAS 线程；当前关系计算基准没有因进程级线程池获得可测收益，单线程可避免长期驻留大量空闲原生线程。每次小时级保留期维护完成后，标准输出写一行 `MONITOR_RUNTIME`，只包含进程运行秒数、存活/采集中的工作线程数、Python 线程数、清理运行数以及 SQLite、WAL、回购证据字节数，不包含数据库路径或本机身份。服务自身不创建无界日志文件；若把标准输出重定向到文件，应由启动方式设置轮转和容量上限。`/healthz` 会核对调度器与每个长期工作线程，线程异常退出时返回 `503 degraded`，而不是无条件报告正常。

`--smart-money-symbols` 仅作为旧启动命令的兼容参数保留，当前集成监控固定要求 `BTCUSDT`；传入其他合约会在启动时明确失败。扩大到其他资产需要先给出消费者、研究口径和独立验证，不能把 BTC 参数静默套用到别的市场。

## 数据含义

### C2C 核算

- C2C 广告来自 Binance 官方公开 Agent API 的 `ad-list` 与 `trade-methods`，不使用账户 API Key；
- 现货一档来自 Binance 官方公开 Spot `bookTicker`；
- 页面只在 API 返回的最多 20 条广告中筛选满足核算金额、支付方式、限额和库存的样本，“最佳”不代表全市场最优，也不构成可成交承诺；
- 某币种在当前金额和支付方式下没有匹配广告，是本轮查询的明确空结果而不是网络异常；页面会在核算表中列出该币种，不把其他已取得报价降级为“部分来源异常”；
- C2C 广告、现货一档和页面刷新不是原子快照，结果只适合观察与比较，不是订单价格或执行依据；
- 接口依据：[Binance P2P Skill 的公开查询契约](https://github.com/binance/binance-skills-hub/blob/main/skills/binance/p2p/SKILL.md) 与 [Binance Spot REST API](https://developers.binance.com/en/docs/products/spot/rest-api)，核对于 2026-07-25。

### BTC 专业情报

这项监控的当前消费者是在研究 BTC 市场状态、关键价位和结构事件时，需要在一个页面区分慢趋势、日频战术状态、4 小时结构与资金流语境的交易研究用户。它交付的是可追溯的市场状态和前向研究账本，不是综合评分、涨跌概率、买卖建议、仓位或执行入口。

- 一个注册监控、一个长期调度线程和一个页面投影内整合四层信息；没有复制聪明钱采集器、另起服务或增加第二数据库。现货层读取 Binance Spot 公开 `BTCUSDT` 日线、4 小时 K 线与参考价；所有正式状态只使用已闭合的 UTC K 线。各层显示自己的数据截止时间，现货、4 小时或聪明钱局部失败不会清空其他已通过校验的层；
- 月频层复现研究冻结的 Faber 10 月状态。正式目标只使用完整 UTC 月：最近完整月收盘高于此前 9 个完整月收盘均值时为 `BTC Spot 多头研究目标`，否则为 `现金研究目标`。页面同时展示以当前月参考价相对当前边界的距离，但月内穿越只标为临时位置，不提前改写正式月频目标。独立前向账本只记录部署后在月首 `00:01Z` 之前及时冻结的月末信号，随后追加 Binance Spot `00:01Z` 一分钟 K 线开盘执行代理、15/30bp 成本、目标切换和完整持有周期；首次部署时不倒灌当前或历史月份；
- 日频层分别回放 Donchian `20/30/60/90` 四个组件。突破各自上轨后进入活动状态，活动期间退出边界只向上跟随通道中点；页面展示每个组件的状态、边界角色与距离。四组件活动比例只归类为强上行、过渡或弱势/防御状态，不作为概率或收益分；月频与日频只组合成“慢趋势与日频通道一致、月频多头中的日频回撤风险、现金状态下的日频反弹、防御、分歧”五种解释，不再压成一个总分；
- 4 小时层使用 `ATR14 / ADX14 / EMA20 / EMA50` 描述当前环境。枢轴必须经过左 3 根、右 3 根确认，确认前不可用；支撑/阻力只由当时已确认的枢轴在最近 1080 根内形成，按 540 根半衰期衰减，并要求至少两个相隔 12 根的锚点。每个当前区间使用实际锚点时间、角色和价格生成稳定版本号；页面分别显示首次形成时间与当前精确版本的最近锚点确认时间，不把后来更新的边界伪装成早期已知事实；
- 前向事件账本只从该版本实际部署后开始。价格首次触碰当时已知的最近支撑或阻力时，系统在同一 SQLite 追加不可变 `PENDING` revision，并冻结水平版本、事件方向、区间、完整研究特征、月/日/4h 市场语境、触碰收盘、ATR、30/50bp 成本与算法版本；随后 6 根闭合 4 小时 K 线内，先达到沿结构方向 `1 ATR` 记为反应，先穿越区间外 `0.5 ATR` 记为突破，否则记为未解决。结果 revision 同时保存下一根开盘代理、结果收盘、方向化收益、ATR 收益、成本后收益和最大有利/不利波动。未解决样本保留在覆盖率分母；服务恢复时，只允许最新一根闭合 4 小时 K 线产生新预测，任何已有后续闭合 K 线的未登记触碰均标为遗漏诊断；
- 研究给出的概率层只有实验规范，没有可部署的冻结模型工件、校准参数和运行契约，因此页面明确显示“概率模型尚未部署”，`P(反应) / P(突破) / P(未解决)` 与研究优先级保持为空。未来只有在独立时间样本外验证、概率校准、成本敏感阈值和模型工件都冻结后才能增加；
- Smart Money 只作为次级语境层，继续显示 30m/1h 的巨鲸、非巨鲸与总流量结构，并保留 `INSUFFICIENT_EVIDENCE / CONTEXT_ONLY` 权限。它不会确认或否决月频、日频和 4 小时状态，也不会进入一个伪精确的综合分；未被页面和特征使用的仓位总览陈旧只记录在语境层，不降级已有完整 30m/1h 行的整体监控状态；
- 日线与 4 小时历史分别限制为 900 根和 1500 根，响应正文、分页、超时、退避、缓存、事件保留期和事件总数都有上限。K 线重复、时间不连续、历史不足、字段变化、陈旧来源或限流时，对应层保持不可用并显示具体诊断；不插值、不用旧状态冒充当前状态；
- 现货公开接口依据 [Binance Spot Market Data endpoints](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints)；研究公式、参数、证据等级与前向验证边界来自 Halpha Research 冻结方案，实现不在运行时导入 Research 仓库。

### BTC 聪明钱语境层

- Smart Money 来自 Binance 网页实际使用的 `/bapi/futures/v1/public/future/smart-money/...` 接口；它们未出现在正式 Developer API 文档中，没有稳定性、速率限制或变更承诺；

### 山寨币异动雷达

- 全部来源统一为 Binance 官方公开 USDⓈ-M：`exchangeInfo`、全市场 `ticker/24hr`、闭合 5m/1d `klines`、`premiumIndex` 与 `openInterestHist`。所有请求均未登录、无 Cookie、无 API Key，只读取公开合约市场数据；接口依据核对于 2026-08-08；
- “全市场”指每轮读取当前处于 `TRADING` 的 USDT 永续合约，只保留 `underlyingType=COIN`，并排除 BTC、内置稳定币名单和已知杠杆代币名单；因此会包括没有 Binance 现货交易对、但存在 USDⓈ-M 永续合约的山寨币。所有剩余合约先经过 24h 流动性门槛；达到门槛的合约读取闭合 5m K 线并完成同口径特征分析，再按异动分、15m 波动与流动性选出最终展示候选。扫描覆盖是整轮采集元数据，页面只在候选表上方显示一次全市场、流动性达标、K 线读取、完成分析和展示数量，不在每行重复；
- 默认 24h 成交额门槛为 `5,000,000 USDT`，每轮最多读取 240 个达标合约的 K 线、展示最多 30 个候选，后台周期 3600 秒并附加最多 30 秒抖动；可见页面观察时按每根新闭合 5m K 的 300 秒周期采集，候选并发最多 6 个。若达标合约超过读取上限，只使用全市场 24h 行情的异动与流动性排序决定本轮 K 线读取范围，并在本轮扫描摘要中明确标记；这些边界可由上面的 CLI 参数调整，但提高范围前应评估 Binance 当前请求权重与同机其他监控占用；
- “价格位置”覆盖本轮已经通过流动性门槛并完成连续 5m 分析的全部合约，而不是只覆盖最多 30 个最终候选。每个合约最多保留 220 根规范化闭合 UTC 日线，至少需要连续 90 根才进入表格；价格区间最多使用最近 180 根。相同闭合日直接复用可删除重取的 gzip CSV 缓存，新闭合日出现后从末尾重叠 3 日增量校正，不把陈旧或断档缓存用于新状态；
- 价格位置保留独立、可排序的当前价、24h/7日/30日/90日涨跌、90日区间位置、距最多180日高低点、20/60日均线结构、30日振幅与实际日线覆盖，不把这些事实压成另一个模糊总分。状态按明确优先级标记：24h≤-12%或3日≤-20%为“暴跌”，24h≥15%或3日≥25%为“暴涨”，7日≥25%、距区间高点不超过12%且高于20日均线为“拉升中”；其后检查前高附近、高位整理、底部横盘、低位反弹、持续下跌、高位、底部和区间中部。状态只描述可复核的价格形态，不证明存在操纵主体；
- “上一轮拉升峰值”必须同时满足局部11日高点、此前14日低点到峰值至少上涨30%，并在此后14日内至少回撤18%；因此当前仍在发展的上涨不会被误当作上一轮。价格位置标签使用本轮滚动24h行情的当前价和最新闭合日线，分别显示两个截止时间；当前价结论有效期为15分钟。SQLite 只原子替换一份当前价格位置快照，不按每个5分钟轮次复制全表；候选与后续行情检验仍按有界历史规则持续记录；
- 评分只使用同一 USDⓈ-M 永续合约连续、已闭合且仍在有效截止点内的 5m K 线。主要特征包括 15m/1h 涨跌、最近 15m 相对之前 45m 的成交额与成交笔数放大、主动买入成交额占比、前高突破、区间位置、波动压缩和相对 BTCUSDT 永续合约的 15m 表现；资金费率与最终候选的 15m OI 变化也来自该合约，不再把现货和合约的两套微观结构拼接成同一判断；
- 候选表的“综合状态”先形成短线阶段，再用该信号截止时已经闭合的日线和同一根闭合5m收盘价判断其价格位置；不会把价格位置标签使用的稍晚滚动价倒灌到冻结信号。明确组合包括底部蓄势、低位启动、超跌反弹加速、前高突破测试、冲高回落风险、高位回落/受阻风险和下跌延续；其他组合显示“待位置确认”且不输出方向。综合状态用于描述可复核的市场形态，不证明存在操盘主体；
- 页面明确展示时效口径：每根闭合 5m K 重算，短线主判看 15m，趋势背景看 1h，波动压缩比较覆盖约 2 小时 15 分，流动性与部分风险条件看 24h；“结论有效至”为市场截止后 15 分钟，到期后必须等待新采集。同轮全部候选的有效时间或市场截止一致时，页面在表格上方只显示一次；存在差异或缺失时才保留逐行列。“复核节奏”只是基于 5m 更新频率的风险检查要求，不是期望盈利持仓期；当前没有包含手续费、滑点的样本外回测，因此不会输出虚构的持仓时长；
- 原始短线阶段仍为“蓄势观察、启动、加速、尾声风险、回落确认、尚未形成”。`异动强度`、内部蓄势/启动分和 `尾声风险` 都是 `0–100` 的规则化异动分，不是证据充分性或经过样本外校准的概率，也不能证明存在操纵主体、保证后续上涨或构成买卖建议。页面不再用这些分数派生“高/中/低证据”标签；“关键事实”只列出对本轮规则归因贡献最大的已观测市场事实，不代表独立来源佐证或新闻事实；
- 每轮候选快照都继续写入 `monitor_sample`，并用合约范围序列键与此前现货历史隔离。页面以“异动候选 / 价格位置 / 异动强度历史 / 后续行情检验”四个标签承载候选主表、当前日线位置、单币种历史和样本检验，标签选择写入 URL，刷新后保持不变。综合状态首次出现、发生变化，或同状态持续4小时仍未建立新样本时，系统在结果未知时冻结合约信号截止价、短线触发、日线位置、方向和该状态指定的15分钟、1小时或4小时时限；没有明确方向的状态不进入准确性统计。到期后即使合约已经离开候选列表，也会用该合约与 BTCUSDT 永续合约同期连续闭合5m K线计算绝对收益、相对BTC收益、沿判断方向的最大顺向波动和反向最大逆向波动；不插值、不用当前价格替代缺失历史；
- 新融合规则启用后，每个融合检验任务都会同时冻结同币种、同信号截止、同期限的原短线规则基线，页面只在两边都完成时成对比较。原短线历史不会被事后价格位置回填成融合样本；融合规则的当前统计从实际部署后的新信号开始，避免把当下分类器伪装成当时已知判断。只有绝对方向一致且相对 BTC 超过暂定的 `±0.5` 个百分点噪声带才记为“方向一致”，反向越过噪声带记为“方向相反”，其余为“未形成显著方向”。该口径不含手续费、滑点和可成交性，不能当作收益回测；页面先展示到期覆盖率作为防选择偏差护栏，每个“综合状态 × 期限”至少完成30例后才显示方向一致率，否则明确显示样本积累中；
- 检验任务、完成结果和无法取得连续行情的状态均保存在同一个 SQLite，并与信号来源运行记录绑定，随现有保留期级联清理。检验补采按每轮最多36个到期任务执行，失败不会覆盖当前行情结果，也不会另起服务或无限增加线程；
- 单个合约的 K 线未通过连续性、新鲜度或字段校验时，不把不完整记录放入主候选表，具体合约和原因保留在采集诊断中；最终候选的资金费率或 OI 失败时，仅对应字段保持为空并在原位置说明原因，其他候选仍照常展示。全市场基础行情失败、陈旧或限流时不生成新评分。HTTP 418/429 遵守 `Retry-After` 并打开共享有界退避，不用上一轮数据冒充当前结果；
- 首版明确不把链上数据混入市场评分。跨链地址、原生币与代币合约映射、区块确认时间和交易所地址标签口径不一致；在没有指定链、合约地址和可核验公开来源前，合并成一个“链上活跃度”会制造伪精度。后续应按具体链和币种建立独立事实，再验证其是否改善阶段识别；

### BTC 市场关联与相对强弱

- 资产范围固定为内置的 2026-07-21 研究快照：411 个 Binance Spot USDT 原生加密/锚定资产（含 BTC 参考，410 个比较对象）；运行时不依赖或改写 Research 仓库；
- 数据来自 Binance 官方公开 Spot `1d` K 线，只使用已闭合的 UTC 日线；同一闭合日已经缓存时不会重复请求，新的闭合日出现后才增量补取；
- 主窗口为最近 365 个连续对齐日收益，最低需要 120 个观测；计算 Pearson、Spearman、BTC Beta、R²、波动倍数，以及相对 BTC 的 7/30/90 日累计强弱；
- 监控服务使用已锁定的 pandas/numpy，不复制研究侧 HAC 推断、FDR、多来源交叉核对和证据快照平台；页面的“强/中等/弱”仅指 Pearson 绝对值区间，不表示统计显著、预测或可交易；

- 原研究结论仍为 `SUPPORTS_WITHIN_SCOPE`，只支持既定样本内的关联描述；不支持因果、领先关系、未来预测、交易信号或 Alpha。

### A股与港股通回购情报

这项监控的当前消费者是需要依据回购事件阶段、官方证据、实际回购规模和港股通可买资格快速做交易研判的用户。主清单只交付满足当前质量契约的回购情报；候选、缺失和不确定记录由系统隔离并在次级异常入口说明，不要求用户逐条复核。它不是回购事件驱动策略的方向或收益模型。

- A 股公告索引每小时读取上交所官方公告查询和巨潮资讯沪/深市公开检索，默认只看最近 7 个自然日。标题分类区分方案、首次实施、进展、变更、完成/终止、注销、出售已回购股份等生命周期；限制性股票、业绩承诺或业绩补偿回购、子公司回购、质押式回购及股东名册等非目标披露明确排除。只有官方索引、明确事件分类和可读 PDF 原文共同满足质量门时才进入主清单；
- A 股公告原文按“最新候选优先”下载，每轮最多 20 份。上交所原文不可直接取得时可使用同一候选的巨潮公开 PDF；PDF 必须通过文件、页数和可读性校验才会进入内容寻址证据目录。扫描件或无文本 PDF 会保留原文，不把 OCR 或推测字段写成事实。首次开启或尚有公告原文未获取时，来源状态为 `PARTIAL`；页面会显示具体数量及这些记录暂不展示的影响，后续小时轮次继续获取；
- A 股结构化参考每 6 小时最多读取一次东方财富公开回购列表，作用仅是定位同证券、同披露日附近的候选数值。只有累计股数、累计金额、最高成交价、最低成交价四项都能在官方 PDF 正文中匹配，且金额除以股数落在公告成交价区间内时，才把累计值写入官方公告 revision；计划金额也必须能在同一正文中匹配后才参与进度计算。A 股规则披露累计值而非逐日成交明细，因此除“首次实施”可确定为 1 个执行日外，不用公告起止日期推算实际执行天数；
- 港股事实来自港交所主板和 GEM 的 Daily Share Repurchase Report。解析器只接受已锁定的 11 列或 14 列表头契约，只投影交易场所为 HKEX 的实际回购行；跨市场行、未知场所、币种冲突和表头变化均隔离并显示诊断。常规轮次读取最近 7 日，并在同一来源下向前补取最多 120 个自然日、每板块每轮最多 120 份尚未取得的日报。页面按证券代码、股份类别和实际回购日合并每日行，以“当日累计等于当日买入”识别新一轮起点；只有首日与随后每日累计增量全部吻合且对应当前来源完整时，才展示本轮完整执行天数、累计金额和加权均价。历史尚未覆盖起点时，执行天数只显示最低值，本轮累计金额和均价保持为空；近 7 日金额与均价可作为明确标注的局部信息展示，但不参与完整累计值排序；
- 购买资格只分为“可购买”和“不可购买”：A 股统一为可购买；港股分别读取上交所、深交所官方当前名单，任一路线包含该证券即为可购买，只有两条来源都成功且均不包含时才为不可购买。任一名单未完整取得且没有当前正向命中时，受影响港股暂不进入主清单，不使用陈旧名单给出负面结论；
- 默认回购采集周期为 3600 秒并附加最多 300 秒抖动，但只在上述两地交易时段并集自动执行；时段依据[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)、[深交所交易时间](https://www.szse.cn/www/English/services/trading/tradOverview/)和[港交所证券市场交易时间](https://www.hkex.com.hk/Services/Trading-hours-and-Severe-Weather-Arrangements/Trading-Hours/Securities-Market?sc_lang=en)，交易日、节假日和半日市复用已锁定的 `exchange-calendars`，不在项目内另造节假日表。港交所日报、A 股结构化参考、目标 A/H 股行情和公开业绩参考最多每 6 小时刷新一次，沪/深港股通名单最多每 24 小时刷新一次。行情参考提供现价、当日或最近交易日涨跌幅和总市值；东方财富批量行情不可用时改读腾讯公开行情的同口径字段。业绩参考独立读取东方财富 F10 的命名字段：年度 ROE 采用最近完整财年，营业收入同比和归母净利润同比采用最新已披露报告期，并保留两个报告期日期。行情或业绩任一来源失败只清空自身字段，评分按输入覆盖度降权；不把腾讯行情中的未确认序号字段当作业绩。所有参考只进入衍生计算，不覆盖官方回购事实。HTTP 超时、响应大小、批次、历史窗口、重试和 `Retry-After` 退避均有上限，单个来源失败不会丢弃其他来源已经通过校验的事实；
- 官方文件以 SHA-256 内容寻址、原子改名方式落盘；数据库在同一短事务中追加实体 revision、更新来源检查点并登记证据引用。读取本机证据时重新核对大小和 SHA-256。有效的空事件扫描不会清空已有实体；普通运行记录过期后，回购 revision、复核和证据仍按独立保留期管理。证据数据库行清理后若文件因瞬时占用未能删除，后续维护会在安全目录边界内扫描并重试旧孤儿文件，不把失败路径留在无界内存队列；
- 页面首屏显示近 24 小时新增、回购情报、执行类事件和“高吸引力”数量，以及市场、事件阶段、关注分类、购买资格和代码或名称筛选。购买资格使用“可购买”“不可购买”两个复选项，默认只选择可购买，可同时勾选两项查看全部可判定记录；A 股和可通过港股通买入的港股在证券名称旁显示绿色圆点，不另占一列。列表分别展示涨跌幅、回购吸引力、年度 ROE、营收/净利同比、实际执行天数、累计股数、累计金额、回购均价、现价、现价相对均价和回购金额占市值；详情同时显示 ROE 与增长数据的报告期。全部数值列可排序，局部口径排在完整值之后。点击证券代码或名称在新标签页直达 TradingView 专业图表：沪市使用 `SSE`、深市使用 `SZSE`，A 股保留六位代码；港股使用 `HKEX` 并去掉展示代码左侧补零。点击该行其他位置打开本机情报详情，不再保留“查看详情”列。关注分类仍只按事件阶段安排阅读顺序：首次实施、方案变更、出售已回购股份和港股实际回购为“优先研判”，方案/审议和实施进展为“持续跟踪”，完成/终止和注销为“状态更新”；事件阶段、关注分类和非直观衍生列的规则在对应字段旁按需解释，不使用常驻方法提示重复基础设计要求。只有确实影响当前清单完整性的来源、公告原文或读取问题才显示在表格上方的“数据来源与问题”中，并具体说明问题数量和受影响记录是否展示；没有问题时不保留来源状态占位。清单纵向使用页面滚动，表格自身只承担横向滚动；超过 50 条时先完成全量排序再分页，切页后页面回到清单起始位置，右下角提供回到顶部入口。采集诊断统一从标题区弹窗查看，不再占用表格下方空间。人工入口仅用于纠错或补充，并隐藏在详情底部。为保持本机页面查询有界，每次最多读取最新 19999 个原始实体并聚合成证券级清单，达到上限时会明确标记；高开销聚合按持久化版本和分钟桶保留一个有界进程内缓存，列表响应只发送排序、筛选和展示需要的字段，完整证据与 revision 仍在点击详情时按需读取；
- “回购吸引力”以 50 为中性起点，权重为：本轮实际回购金额占市值 25%、现价相对完整本轮回购均价 20%、计划进度或近 7 日实际执行频度 15%、最近完整财年 ROE 12%、最新报告期营收同比 8%、最新报告期归母净利润同比 10%、披露时效 10%。缺失值不填零，按来源可靠性与有效输入覆盖度降权；覆盖不足 35% 或少于两类有效输入时不出分。70 分及以上显示“较高”，55–69.9 分显示“中等”，其余显示“较低”。港股历史未形成完整本轮金额与均价时，近 7 日局部值不进入相应评分项；不可通过港股通买入的港股不出分，名单未完整取得的港股不进入主清单。该启发式未经收益校准，不等于上涨概率、推荐买入、仓位或预期收益；是否改善事件驱动策略仍需后续冻结样本做前瞻检验；
- 公开来源契约于 2026-08-07 做过真实读取核对。入口包括[上交所公告](https://www.sse.com.cn/disclosure/listedinfo/announcement/)、[巨潮资讯](https://www.cninfo.com.cn/)、[上交所沪港通名单](https://www.sse.com.cn/services/hkexsc/disclo/eligiblead/)、[深交所深港通名单](https://www.szse.cn/szhk/hkbussiness/underlylist/)、[港交所回购日报](https://www3.hkexnews.hk/reports/sharerepur/sbn.asp)、[东方财富回购数据页](https://data.eastmoney.com/gphg/)和[腾讯行情](https://stock.qq.com/)。这些公开页面或内部查询契约可能变化，监控会把契约变化显示为来源失败，而不是继续沿用旧解析结果。

### 市场关键事件日历

这项监控的当前消费者是在下单、调仓或决定是否隔夜持仓前，需要知道未来宏观风险窗口的股票与加密资产交易研究用户。它交付确定的发布时间、发布前市场一致预期、官方实值、预期差和固定公式方向判断；不把新闻传闻、券商观点或社区活动混入主日历。

- 发布时间来自[纽约联储经济指标日历](https://www.newyorkfed.org/research/calendars/nationalecon_cal)、[美国经济分析局机器可读发布日程](https://www.bea.gov/news/schedule/icalendar)与[美联储 FOMC 日历](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)。纽约联储来源覆盖 CPI、非农、PPI、零售销售、JOLTS、ISM、工业产出、消费者信心、耐用品与住房等预先筛选事件；BEA 作为 GDP、PCE、国际贸易和企业利润的规范来源，避免同一事件被两个日历重复展示；
- CPI 与就业的实际值来自[BLS 公共数据 API](https://www.bls.gov/developers/)：CPI 同时读取总体与核心 CPI 的季调环比、未季调同比；非农使用总非农就业月增量，失业率使用 U-3。六个序列在一次请求中批量读取，并且只有数据所属期恰好等于该次事件应发布月份时才绑定为本次实值；旧月份结果不会冒充刚公布数据。BLS 日历订阅页面在当前运行环境拒绝自动读取，因此发布时间由纽约联储官方日历提供，不绕过其访问限制；
- 市场一致预期来自[Forex Factory 经济日历](https://www.forexfactory.com/calendar)提供的本周公开 JSON 导出。该来源只负责 `forecast` 与 `previous`，不取代官方日历或官方实值；系统只接受 USD、明确指标名且与官方发布时间相差不超过 30 分钟的记录。本周导出最多每小时读取一次，发布前最后取得的预期会冻结；发布后才取得的 forecast 不会回填成事前预期。来源不可用、指标缺失或匹配冲突时，预期差和方向保持为空；
- CPI 固定方向分为 `-[40% × (CPI 环比预期差 ÷ 0.1 个百分点) + 60% × (核心 CPI 环比预期差 ÷ 0.1 个百分点)]`。就业固定方向分为 `-[65% × (新增非农预期差 ÷ 5 万人) + 35% × ((预期失业率 - 实际失业率) ÷ 0.1 个百分点)]`。分数不低于 `+0.5` 为风险资产短线“偏多”，不高于 `-0.5` 为“偏空”，其余为“中性”；任一必需输入缺失就不出分。详情页显示实际输入、预期差、公式版本、阈值、固定解读和需要用美元、美债收益率与价格确认的研究动作。该启发式解释利率压力方向，未经收益校准，不等于交易指令、上涨概率、仓位或预期收益；
- 精确时间统一换算为北京时间。FOMC 页面尚未公布具体时刻时只展示美国东部日期和“时间待公布”，不把常见发布时间当成官方事实。每个事件保留官方日历、发布页、来源时区、检查时间以及最近一次时间变化；相同事件的日期或时间发生变化时累计记录，不覆盖变化痕迹；
- “准备优先级”是确定性规则：高影响事件在 24 小时内为“立即准备”，72 小时内或中影响事件在 24 小时内为“提前准备”，高影响事件在 7 天内为“本周关注”；最近调整且已进入 7 天窗口的时间会提升优先级。影响级别按事件类型固定，不使用当期结果方向，不表示买入、卖出、波动概率或预期收益；
- 页面以“未来事件 / 历史事件”标签切换。未来页先显示进入准备窗口的事件，再显示最近 CPI/就业结果、未来两周日期网格和可筛选日历；列表增加市场预期以及“官方公布 / 方向”。详情页展示如何解读、预期、实值、预期差、预设公式和计算输入。历史页从启用后的首个采集时点开始，按事件保存发布前预期、发布结果与后续修订，不补录此前事件；超过 50 条分页。点击卡片、日历项、未来列表行或历史行都进入同一详情；
- BEA、纽约联储各月份、FOMC 和 BLS 分别失败隔离。确实影响当前页面的信息在用户看到事件卡片和日历前具体说明；健康来源不占据首屏。成功响应以有界原文、SHA-256 与结构契约哈希随运行保留 90 天，便于追查时间变化；不会增加第二数据库、独立服务或额外线程池；
- 默认基础周期为 21600 秒并附加最多 900 秒抖动，未来窗口为 60 天、最近回看为 7 天。CPI 或非农进入未来 24 小时后，调度最多每小时更新一次一致预期；最后 1 小时会按不短于 15 分钟的节奏对齐发布时点。到时仍未取得对应月份官方实值时，发布后 5 分钟内每 60 秒、随后 10 分钟每 120 秒、再到 45 分钟每 300 秒查询 BLS，取得匹配月份后立即恢复正常节奏；该上限连同 6 小时基础检查控制在 BLS 未注册公共日额度内。日程来源仍最多每 6 小时读取一次，快速轮询不重复抓取全部日历；窗口上限、HTTP 超时、正文大小和重试次数都有边界。

## 低复杂度边界

- 一个操作系统进程、一个 FastAPI 页面、一个 SQLite 数据库；BTC 专业情报、山寨币异动雷达和 BTC 关系监控只增加同目录下可删除重取的规范化 K 线缓存，回购监控只增加同目录下有配额和独立保留期的内容寻址证据目录；
- SQLite 使用 WAL、外键和短事务；一次采集的运行、原始响应、样本、问题、BTC 结构事件 revision、市场事件 revision 以及回购来源状态/revision/证据引用原子提交，全库保留期清理最多每小时执行一次；回购原始文件先原子落盘再登记，数据库不会指向半写文件；
- 每个注册监控使用一个长期工作线程，超时与异常不阻塞其他监控；BTC 关系和山寨币异动采集只在单轮内部使用固定上限的临时线程池，OpenBLAS 未显式配置时固定为 1 个原生线程。关闭时调度器先向采集客户端广播停止信号，不再启动新请求，并以所有工作线程共享的总截止时间等待当前有界请求退出；
- BTC 专业情报后台每 600 秒采集并增加至多 30 秒随机抖动，可见页面观察时由 15 秒心跳按 60 秒时效门槛请求采集；山寨币异动雷达后台每 3600 秒采集并增加至多 30 秒抖动，观察时按 300 秒闭合 K 线周期请求采集。重复心跳合并为一个待执行事件；Spot、Smart Money 或 USDⓈ-M 的 418/429 退避仍只停止对应公开来源的外部请求，不阻塞其他监控；
- 页面左侧用绿色“监控中 / 采集中”和灰色“已关闭”表达调度状态；数据区域另行区分最新结果、上一轮结果与历史快照。页面只读取已提交且通过校验的记录；最新采集失败时仍可显示上一次已校验样本及其截止时间；
- 历史曲线按真实采集时间分段，不跨越长于采集周期容忍阈值的空档；空档标记为“未采集时段”，不会拟合、插值或用领域默认值连接；
- 缺失或异常字段显示为空值符号并在原位置说明原因，不以假数据、拟合值或领域默认值补齐；近期失败明细默认收在次级“采集诊断”中；
- 没有消息队列、动态插件发现、前端构建、图表依赖、第二数据库或通用告警平台；
- 服务不会被 Halpha 产品代码导入、启动或停止，也不修改当前 L4 产品事实。

SQLite 样本使用关系型运行/索引字段，并在同一事务中保存每个监控的紧凑 payload；它不是 JSONL 文件，也不依赖逐行扫描查询。

## 注册新监控

1. 在 `src/halpha_monitor/monitors/` 新建独立模块，实现 `RegisteredMonitor` 的字段和 `collect()`。
2. `collect()` 返回 `CollectionBatch`；通过校验的样本放入 `samples`，局部失败放入带 scope 的 `issues`。
3. 只在 `monitors/__init__.py` 增加采集 CLI、settings 构造和显式注册；跨监控的存储容量/保留期参数仍由服务入口统一传给同一个 store。
4. 为采集逻辑、部分失败和页面投影增加对应测试，并让 built-in 契约测试覆盖新注册对象。

注册对象声明采集间隔、筛选项、表列和投影类型，共享进程不理解各监控的业务公式。时间序列继续复用通用表格和历史图；只有事件事实确实需要来源健康、原始文件和人工校正时，才增加边界清楚的专用投影。实现 `ConfigurableMonitor` 时，配置读写必须原子化，`collect()` 每一轮只使用一个不可变配置快照，避免页面保存与采集线程拼接两套条件。需要随运行保留的有界文本响应使用 `CollectionArtifact`；只需要当前全表投影、且逐轮复制会造成无价值增长时使用有大小上限并与运行原子提交的 `ProjectionSnapshot`；需要跨普通运行保留期审计的官方二进制文件使用内容寻址证据和 append-only revision，不能把大文件塞进 SQLite 或另建数据库。大范围官方日线如需增量复用，只保留可删除重取的规范化缓存，不能把缓存冒充当前样本或研究证据。
